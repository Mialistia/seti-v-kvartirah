# Сайт проекта «Сети в квартирах»

Тексты сайта пишутся в Notion (база «Страницы сайта»). Раз в час GitHub Actions выгружает отмеченные страницы в `docs/*.md`, собирает сайт MkDocs Material и публикует его на GitHub Pages. Снимок выгруженных страниц сохраняется в ветку `notion-content`.

## Настройка

1. Notion → https://www.notion.so/profile/integrations → New integration → Internal → скопировать токен.
2. В Notion открыть страницу «Сайт проекта «Сети в квартирах»» → ••• → Connections → добавить интеграцию.
3. GitHub → Settings → Secrets and variables → Actions → New repository secret:
   - `NOTION_TOKEN` — токен интеграции;
   - `NOTION_DB` — `cd117d20433441e79eedfee7d44bae59` (ID базы «Страницы сайта»).
4. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
5. Actions → «Сайт из Notion» → Run workflow. Через 1–2 минуты сайт откроется по адресу `https://<логин>.github.io/<репозиторий>/`.

## Оборудование для калькулятора

Калькулятор считает по методике И4 и подбирает оборудование из базы Notion «Оборудование К Телеком» (ID `6f5df9461b6643f4a99ff5519f134c54`). При каждой синхронизации база выгружается в `docs/assets/data/equipment.json` (одна модель — одна строка) и попадает в ветку `notion-content`.

- В каталог попадают все модели базы: парк К Телеком и рынок (И3). Модели на распродаже («Заказ партии в офис» = «нет — распродажа остатков») движок исключает сам и показывает среди исключённых с причиной.
- Обязательные поля: «№», «Модель», «Тип», «Wi-Fi», «Диапазоны», «WAN, Мбит/с» и цена — для парка «Цена, ₽», для рынка «Цена рынка (медиана), ₽». Записи без них пропускаются, их список — в журнале запуска.
- Пустые «ЭИИМ …» — значения по умолчанию И4; пустое «Потребление узла, Вт» — медиана рынка И3 по классу скорости, без класса — 7 Вт; «Функции (И3)»: да — 1, частично — 0,5, нет — 0.
- Если подходящих записей меньше 10 или выгрузка не удалась, публикация не останавливается: остаётся прежний файл, в журнале запуска — предупреждение.
- Интеграция Notion должна иметь доступ к базе: если база лежит вне страницы «Сайт проекта…», добавьте интеграцию в ••• → Connections самой базы.
- Другая база — секрет или переменная `NOTION_EQUIPMENT_DB`.
- Таблица «Подобранное оборудование» показывает только модели К Телеком: «Эконом» (наименьшая TCO), «Оптимальный» (наибольший балл S, рекомендуется), «Премиум» (наибольшие TCP<sub>z</sub> и P<sub>z</sub>); совпадающие — одной строкой. Кнопка «Аналоги» — параметры подбора и 2–3 примера с рынка. Если в парке нет подходящей модели, показывается ближайший вариант К Телеком (условно). Данные — `R.kt` движка (`engine_i4 1.2`); поля эталона И4 (`rec`) не менялись.
- Контрольные примеры И4 считаются на замороженном каталоге `tests/fixtures/equipment_i4.json`, поэтому правки базы в Notion их не ломают. Эталон меняется только вместе с пересчётом в отчёте И4.

## Правила для страниц в Notion

- На сайт попадают только страницы с галочкой «Опубликовано».
- «Адрес» — латиница, цифры, дефис; главная — `index`.
- «Порядок» — место в меню; «Раздел» — группа меню.
- Формулы — блоками формул, картинки — загружать файлом.

## Порядок изменений

Ветка `main` защищена: прямые коммиты, перезапись истории и удаление запрещены.

1. Резервная копия: ветка `backup/ГГГГ-ММ-ДД-ЧЧММ` от текущего `main` (такие ветки и теги `backup-*` нельзя удалить или изменить).
2. Изменения — в отдельной ветке (`notion-ai/<задача>` или своей), затем pull request в `main`.
3. Проверка сборки должна быть зелёной; после этого — **Merge**.
4. После слияния автоматически создаётся тег `backup-ГГГГ-ММ-ДД-ЧЧММ` и выпуск в Releases с архивами.

**Откат:** кнопка **Revert** в слитом pull request; к любой прошлой версии — из ветки `backup/…`, тега или архива в Releases.

## Работа без Notion

Все страницы после каждой синхронизации хранятся в ветке `notion-content` (и в архивах Releases), поэтому сайт не зависит от аккаунта Notion. В `main` страницы из Notion могут быть устаревшими.

**Переключиться на правку в GitHub:** сначала перенесите свежие страницы в `main` — Pull requests → New pull request → base `main`, compare `notion-content` → Create → Merge. Затем Settings → Secrets and variables → Actions → вкладка **Variables** → New repository variable: `CONTENT_SOURCE` = `github`. После этого Notion не опрашивается, а сайт собирается из `docs/*.md`.

**Как править страницы без Notion:**

- в браузере: открыть файл в `docs/` → карандаш (Edit) → Commit changes → «Create a new branch» → pull request → Merge; сайт обновится за 1–2 минуты после слияния;
- удобнее: на странице репозитория нажать клавишу `.` — откроется github.dev (VS Code в браузере) с предпросмотром Markdown;
- новая страница: создать `docs/<адрес>.md` и добавить строку в `nav:` файла `mkdocs.yml`.

**Вернуться к Notion:** удалить переменную `CONTENT_SOURCE` или задать `notion`. Внимание: страницы с меткой `generated-from-notion` тогда снова перезапишутся из Notion, ручные правки в них пропадут. Перенесите их в Notion заранее или удалите метку из первой строки файла.

Если Notion недоступен или выгрузка упала, скрипт ничего не удаляет: остаётся последняя удачная версия сайта.
